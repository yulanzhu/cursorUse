# 总结

输入框里的字是临时状态。登录用户是应用状态。网络结果要分清加载、成功、失败和没有数据。不要把这三种状态塞进同一个大对象。

<!-- section: 专业讲解 -->
## 三种别混

- 临时状态跟这一页的 `State` 一起活，页拆了它也走。比如输入中的文字、当前选中的页
- 应用状态要跨过路由仍然在。比如登录用户、购物车里有什么
- 异步界面至少要分开：正在加载、成功、失败、成功但没有数据
- 没有数据不是失败。正在加载也不是一份空白的成功
- 用 `sealed` 把这几种结果写成互斥的类，非法组合就写不出来
- 一堆允许缺失的字段放在一起，会出现又有数据又有错误的脏状态

<!-- section: 大白话 -->
## 大白话

- 临时状态像草稿纸，离开这张桌子就可以扔
- 应用状态像钱包里的证件，换一间房也要带着
- 异步结果像快递。在路上、送到了、送失败、送到但箱子里没有东西，这是四件不同的事

<!-- section: 怎么用 -->
## 怎么用

```dart
sealed class PageData<T> {}

class PageLoading<T> extends PageData<T> {}

class PageReady<T> extends PageData<T> {
  PageReady(this.items);
  final List<T> items;
}

class PageNone<T> extends PageData<T> {}

class PageFailed<T> extends PageData<T> {
  PageFailed(this.message);
  final String message;
}
```

- 界面按这四种去分支，不要用一个布尔再加一个可能没有的列表硬凑
- 输入框的文字留在这一页。登录用户不要只放在某个输入页的 `State` 里

<!-- section: 再讲深一点 -->
## 再讲深一点

- 成功但列表里没有条目，要有自己的界面，不要显示成失败，也不要显示成正在加载
- 失败要能再试。加载中的按钮不要让人连着点出好几个请求
- 临时状态可以提升到这一页的父级，仍然不必升格成应用状态
- 应用状态要能活过路由切换，所以它的主人不该是某一个页面的 `State`

<!-- section: 边界 -->
## 边界

- 不要把临时输入、登录用户和网络结果塞进同一个大对象
- 三种生命周期不同，你分不清谁该在 `dispose` 里结束
- 下一节才谈应用级的一种写法。这里先把边界划开

<!-- section: 收束 -->
## 留下这句

- 草稿纸、证件和快递不要塞进同一个口袋。加载、成功、失败、没有数据，也要分开
