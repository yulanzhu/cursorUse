# 总结

缓存要有失效办法。只有写入、没有失效，用户会一直看到旧数据。密钥不能打进客户端包里，因为安装包会到用户手里，用户可以打开它看到里面的内容。这节只做这个判断，不讲打开包的办法。

<!-- section: 专业讲解 -->
## 失效和不能进包的东西

- 内存缓存和磁盘缓存都算缓存。图的解码缓存、接口响应的缓存，都要能被清掉
- 常见的失效有三种：到了时间就作废，版本变了就作废，用户主动刷新时作废
- 没有失效办法的缓存，会一直把旧价格、旧权限端上来
- 随安装包一起发出去的主密钥，不是秘密。用户能打开包，看到里面的内容
- 混淆不能把打进包里的密钥变成秘密
- 真正的主密钥留在服务端。客户端如果要留，只留这个用户登录之后拿到的凭证
- 凭证放在系统提供的安全存储里，并且服务端能作废它

<!-- section: 大白话 -->
## 大白话

- 没有失效的缓存，像冰箱里一盘不写日期的菜。你不知道它现在能不能吃
- 打进安装包的密钥，像把家里的钥匙印在门上。门会到别人手里

<!-- section: 怎么用 -->
## 怎么用

```dart
class Cached<T> {
  Cached(this.value, this.until);
  final T value;
  final DateTime until;

  bool get fresh => DateTime.now().isBefore(until);
}
```

- `fresh` 是假时，不要再把 `value` 当成现在的数据
- 登出时，上一名用户的缓存必须失效
- 主密钥不要出现在代码、资源或配置常量里

<!-- section: 再讲深一点 -->
## 再讲深一点

- 时间、版本、主动刷新，至少要有一种。更好的是时间加上一个你能主动丢掉的办法
- 安全存储是给用户自己的、可以作废的凭证用的，不是给公司的主密钥用的
- 主密钥如果曾经写进包里，再抄进安全存储，也改变不了包里有一份这个事实
- 登出、切换用户、权限变化，都是缓存该失效的时候

<!-- section: 边界 -->
## 边界

- 这节只判断什么不该进客户端包，不提供打开包、取出内容的步骤
- 不要把混淆当成保密。混淆让阅读变难，不让秘密成立
- 缓存失效也不要做成“永远不缓存”。没有失效办法，才是问题

<!-- section: 收束 -->
## 留下这句

- 缓存要有失效办法。主密钥不能打进客户端包。客户端只留可以作废的用户凭证
