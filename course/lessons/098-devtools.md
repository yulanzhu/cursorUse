# 总结

先分清慢在 `build`、布局，还是光栅。再看重建次数和内存。控制器和订阅没有 `dispose`，会一直留在登记里，动画的节拍也会继续要帧。

<!-- section: 专业讲解 -->
## 先分段落

- UI 时间更久：看构建和布局
- 光栅时间更久：看绘制、图层和图片
- 重建次数异常：看 `setState` 的范围
- `dispose` 里成对卸掉控制器、订阅和焦点节点

<!-- section: 大白话 -->
## 大白话

- 先看是写剧本慢，还是把画面画成像素慢

<!-- section: 怎么用 -->
## 怎么用

- 打开性能页，比较 UI 时间和光栅时间
- 打开重建统计，点进次数异常的组件
- 看内存里有没有一直涨、却从不下去的对象

<!-- section: 再讲深一点 -->
## 再讲深一点

- 构建慢，多半是计算太多或重建太广
- 布局慢，多半是约束套了很多层
- 光栅慢，多半是图层、裁剪或图片太贵

<!-- section: 边界 -->
## 边界

- 工具告诉你时间花在哪，不替你改设计
- 没分清段落之前，不要把代码随机改一通

<!-- section: 收束 -->
## 留下这句

- 先分清三段时间，再看次数和内存。创建了就要卸
