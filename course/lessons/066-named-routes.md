# 总结

字符串路由名没有类型，参数也是一个要自己转型的对象。页面一多，集中的路由表会变成一堆分支。小应用仍然能用，规模上来就不够。

<!-- section: 专业讲解 -->
## 字符串的问题

- `pushNamed` 靠字符串找页面。拼错的路径，编译器不会拦
- `arguments` 的类型是 `Object`，到了页面里再自己转型
- 类型给错，要等到运行时才爆
- 集中的 `routes` 或 `onGenerateRoute` 会随着页面变多，变成一大串分支
- 改一个名字，要自己去翻那些字符串
- 路径片段、查询和 `arguments` 三种通道都没有类型，读的人对不齐

<!-- section: 大白话 -->
## 大白话

- 像门口的纸条上写着房间号。纸条写错一个字，编译的时候没人提醒你
- 你递给下一间房的包裹没有标签，对方只能拆开猜里面是什么

<!-- section: 怎么用 -->
## 怎么用

```dart
Navigator.pushNamed(
  context,
  '/orders/detail',
  arguments: orderId,
);

MaterialApp(
  routes: {
    '/orders/detail': (_) => const OrderDetail(),
  },
)
```

- 只有两三页、又没有参数时，这种表仍然能看懂
- 参数一多，就不要再靠 `arguments` 的强制转型往下走

<!-- section: 再讲深一点 -->
## 再讲深一点

- `onGenerateRoute` 把分支收进一个函数，类型问题并没有消失
- 重新整理结构时，字符串不会跟着改名一起更新。漏掉一个，就是运行时的失败
- 嵌套导航和网页路径栏，用一张平的字符串表很难表达
- 这就是后面声明式路由要出现的原因。栈应该能从数据里说出来

<!-- section: 边界 -->
## 边界

- 很小的应用、没有参数，命名路由仍然可以用
- 它不够，不表示你现在就要手写三件套。一般用路由库
- 不要在新页面上继续加没有类型的 `arguments`

<!-- section: 收束 -->
## 留下这句

- 字符串没有类型，参数也糟糕。页面一多，集中的路由表会变成一堆分支

# 可以向老师问

- q: 拼错路径为什么编译能过
  tone: 平稳
  pause: 340
  say: 因为路径是字符串，不是类型。编译器只看见一个文字值。对不上页面，要到 `pushNamed` 运行的时候才失败。
- q: arguments 为什么容易给错
  tone: 平稳
  pause: 360
  say: 因为它的类型只是 `Object`。交出去的人和接住的人各自转型，中间没有检查。类型不对，运行时才会爆。
