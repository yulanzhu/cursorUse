# 总结

`Image.asset` 读已经登记的项目内图片，`Image.network` 读网络图。`Icon` 是图标字体里的一个字形，不是位图。图要按分辨率准备，解码尺寸要控制，太大的图会占掉很多内存空间。

<!-- section: 专业讲解 -->
## 三种来源

- `Image.asset` 读取 `pubspec` 里登记过的资产
- 同一张图可以放一倍、二倍、三倍，框架按设备像素比挑选
- `Image.network` 拉取网络图，解码结果进内存里的 `ImageCache`
- 这个缓存有上限，而且不会在磁盘上替你留一份一直存在的副本
- `cacheWidth` 和 `cacheHeight` 让解码尺寸变小，从而降低内存
- `Icon` 使用 `IconData`，材料库的 `Icons` 来自图标字体

<!-- section: 大白话 -->
## 大白话

- 位图是一张已经画好的照片，放大了会糊
- 图标字体是字库里的一个符号，改颜色、改大小，仍然是同一个字形

<!-- section: 怎么用 -->
## 怎么用

```yaml
flutter:
  assets:
    - assets/logo.png
```

```dart
Column(
  children: [
    Image.asset(
      'assets/logo.png',
      cacheWidth: 300,
    ),
    Image.network(url),
    const Icon(Icons.place),
  ],
)
```

- 二倍图、三倍图放在 `2.0x`、`3.0x` 目录，文件名和一倍图相同
- `cacheWidth` 的单位是物理像素，按显示尺寸乘上设备像素比
- 标准 `Icons` 不用再登记，自己的图标字体仍要写进 `flutter: fonts`

<!-- section: 再讲深一点 -->
## 再讲深一点

- 解码后的内存大致随宽、高和每个像素的字节一起涨
- 显示很小、原图很大时，不限制解码尺寸，空间就浪费在看不见的细节上
- 网络图的内存缓存会在超出上限后丢掉最久不用的那张，应用进程结束也就没了

<!-- section: 边界 -->
## 边界

- 资产没登记，`Image.asset` 在运行时找不到文件
- 网络图会失败，用 `errorBuilder` 给替身，不要假设链接一直有效
- `Icon` 通常是单一颜色。多色的小图仍然用 `Image`

<!-- section: 收束 -->
## 留下这句

- 图按分辨率准备，并限制解码尺寸。图标字体和图片不是一回事
