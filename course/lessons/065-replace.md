# 总结

`pushReplacement` 用新页面换掉当前页，用户不能再回到被换掉的那一页。`pushAndRemoveUntil` 清掉一截栈。登录成功后常用后者。

<!-- section: 专业讲解 -->
## 换掉和清掉

- `pushReplacement` 把当前路由换成新路由。被换掉的页面离开栈，会 `dispose`
- 它下面如果还有页面，返回会落到那一页，而不是落到被换掉的那页
- `pushAndRemoveUntil` 先压入新页面，再按判断清掉上面的一截
- 判断返回真的那一层留下，它上面的被清掉
- 判断永远返回假，就是整栈清掉后再留下新页面
- 登录成功常用最后这种。不要让返回回到登录页，也不要让登录页下面仍然藏着旧页面

<!-- section: 大白话 -->
## 大白话

- 替换像把最上面一张纸抽走，同时放上另一张。被抽走的那张不再回来
- 把一截栈清掉，像把一叠旧纸都拿走，只留下你刚放上的那一张新的

<!-- section: 怎么用 -->
## 怎么用

```dart
Navigator.pushReplacement(
  context,
  MaterialPageRoute(builder: (_) => const Home()),
);

Navigator.pushAndRemoveUntil(
  context,
  MaterialPageRoute(builder: (_) => const Home()),
  (route) => false,
);
```

- `(route) => false` 表示一层都不留
- 若要留住某一页，就在判断里对那条路由返回真

<!-- section: 再讲深一点 -->
## 再讲深一点

- 替换和清掉都会让被去掉的页面 `dispose`。没保存的输入会一起走
- 要留的数据先写出去，再换栈
- 普通返回仍然是 `pop`。不要用清掉来模拟“回到上一页”
- 清掉改的是用户之后可以回到哪些页，所以只在流程真正结束时用

<!-- section: 边界 -->
## 边界

- 启动页进首页，常常用替换。登录成功进首页，常常用清掉
- 不要在普通的详情页用清掉。用户会失去返回
- 被去掉的页面若仍然握着控制器，要保证它们在 `dispose` 里放掉

<!-- section: 收束 -->
## 留下这句

- `pushReplacement` 换掉当前页。`pushAndRemoveUntil` 清掉一截栈。登录成功后，常用把旧栈清光

  tone: 平稳
  pause: 380
  say: 表示这一层不留。每一层都返回假，旧栈会被清光，只留下你刚压进去的新页面。登录成功经常这样写。
