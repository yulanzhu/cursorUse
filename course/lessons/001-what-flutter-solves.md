# 总结

Flutter 让你用一份声明式代码描述界面，框架负责把描述变成屏幕上的像素。

<!-- section: 专业讲解 -->
## 机制

- 声明式：写下界面该是什么样
- 原生路线常常要为两个系统各维护一套界面
- 描述变了，框架更新对应的那一块

<!-- section: 大白话 -->
## 大白话

- 像点菜。你说要什么，不必冲进厨房指挥每一个步骤

<!-- section: 怎么用 -->
## 怎么用

```dart
void main() {
  runApp(const MyApp());
}
```

- `runApp` 把根组件交给框架
- `setState` 以后再讲，它是在请框架再看一眼状态

<!-- section: 再讲深一点 -->
## 再讲深一点

- 同一份描述可以面向手机、桌面和网页
- 平台差别留在引擎和嵌入层，不留在你每天写的界面里

<!-- section: 边界 -->
## 边界

- 它不替你决定业务规则
- 描述写错了，屏幕上就会错

<!-- section: 收束 -->
## 留下这句

- 你负责把界面说清楚，框架负责让它出现
