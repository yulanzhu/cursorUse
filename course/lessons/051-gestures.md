# 总结

`Listener` 拿原始指针，不进竞技场。`GestureDetector` 参加竞技场。点击和滚动会争这一下，赢了才走确认回调。

<!-- section: 专业讲解 -->
## 观察和争胜

- `Listener` 能看到按下、移动、抬起，它不登记识别器
- `GestureDetector` 把点击、拖拽这类识别器送进竞技场
- 同一个指针可以有多名识别器。它们要么认输，要么等到只剩自己
- 移动超过阈值时，滚动的拖拽通常赢，点击认输
- `onTap` 这类确认回调，要等胜负出来才走
- `onTapDown` 出现更早，之后仍可能被取消

<!-- section: 大白话 -->
## 大白话

- 原始指针像看见手指碰到了桌子，并不知道这是轻点还是要拖
- 竞技场像几个人同时举手，最后只留一个能把这件事做完的

<!-- section: 怎么用 -->
## 怎么用

```dart
Listener(
  onPointerDown: (event) {
    record(event.position);
  },
  child: GestureDetector(
    onTap: open,
    child: const Pad(),
  ),
)
```

- 要按钮的禁用和语义，用按钮，不要用 `GestureDetector` 冒充
- 列表里的点击能工作，是因为轻点时点击赢，滑动时滚动赢

<!-- section: 再讲深一点 -->
## 再讲深一点

- 识别器可以主动认输，也可以在场上只剩自己时获胜
- 父级 `Listener` 能看见事件，不表示子级的点击已经输了
- 横着拖和竖着滚可以同时进场，方向决定谁赢
- 确认回调没来，先想是不是被别的识别器赢走了

<!-- section: 边界 -->
## 边界

- `Listener` 没有胜负，也不提供按钮语义
- 不要用它模拟点击按钮
- 竞技场解决的是这一下手指属于谁，不负责业务上该不该响应

<!-- section: 收束 -->
## 留下这句

- `Listener` 看原始指针。`GestureDetector` 进竞技场。确认回调要等赢了才来

- tone: 平稳
  pause: 340
  say: 屏幕上外层的 `Listener` 只记录按下的位置。它不跟里面的点击抢胜负。
- tone: 平稳

  say: 内层的 `GestureDetector` 才把 `onTap` 送进竞技场。打开的动作要等它赢。
- tone: 加重

- tone: 放慢

## 边界

- tone: 加重
  pause: 400
  say: 不要用 `Listener` 去模拟一颗按钮。它没有禁用态，没有按钮语义，也没有竞技场帮你和滚动分胜负。
- tone: 平稳
  pause: 340
  say: 竞技场只回答这一下手指属于哪个识别器。业务上该不该打开，仍然是你的回调要决定的。
