# 总结

黄黑斜纹表示孩子比约束更大。先读报错里的约束和尺寸。`Intrinsic` 宽高会多一趟布局，不要当默认手段。自定义 `RenderObject` 只在现成组件没法表达这种协议时才有必要，这里不写步骤。

<!-- section: 专业讲解 -->
## 先读报错

- 调试时，孩子画出约束之外，会出现黄黑斜纹
- 报错会写出溢出了多少，并带上当时的约束和孩子的尺寸
- 先看这些值，再决定缩小、滚动、`Expanded`、`Wrap` 或 `FittedBox`
- `IntrinsicWidth` 和 `IntrinsicHeight` 会多一趟布局
- 自己写 `RenderObject` 只在现成组件没法表达这种约束协议时才考虑

<!-- section: 大白话 -->
## 大白话

- 斜纹是孩子撑出了父级给的框
- 先看框有多大、孩子报了多大，再决定怎么收
- 自己造一把尺子之前，先试试现成的盒子和换行

<!-- section: 怎么用 -->
## 怎么用

```dart
Row(
  children: const [
    Expanded(
      child: Text('a long label'),
    ),
  ],
)
```

- 文字在 `Row` 里容易沿水平方向溢出
- 用 `Expanded` 先给它一个有限宽度，让它在这个宽度里排

<!-- section: 再讲深一点 -->
## 再讲深一点

- 溢出说明约束是有界的，只是孩子比这个上限更大
- 无界报错是父级根本没给上限，和黄黑斜纹不是同一句报错
- `Intrinsic` 为了问孩子本来想要的宽高，会额外排一次

<!-- section: 边界 -->
## 边界

- 发布版本里通常不画这道斜纹，溢出本身仍在
- 现成的 `Flex`、`Stack`、`Wrap` 和盒子能表达时，不要自己写渲染对象

<!-- section: 收束 -->
## 留下这句

- 先读约束和尺寸。自定义布局不是溢出的第一步
